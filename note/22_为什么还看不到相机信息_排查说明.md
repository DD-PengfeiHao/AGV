| 你想看的 | API / UI 位置 | 旧版页面有没有 |

报告 curl 验的是 **JSON 字段**，不是「浏览器一定能看到彩色实拍」。

## 3. 60 秒自检（在你浏览器打开的那台机上执行）

```bash
# 1) 是否已是「人脸 HTTP」那一版？
curl -s http://127.0.0.1:19999/api/health | jq '{ok, web_face_api, face}'

# 2) 相机元数据是否存在？
curl -s http://127.0.0.1:19999/api/state | jq '{cameras_meta, camera_info, camera_streams, cargo}'

# 3) 有没有帧？
curl -s -o /tmp/cam.jpg -w "%{http_code}\n" http://127.0.0.1:19999/api/camera/cam_front/snapshot
file /tmp/cam.jpg   # 应是 JPEG；若 PPM/失败，浏览器 <img> 经常空白
```

| 结果 | 含义 |
|------|------|
| `web_face_api` 缺失 / `cameras_meta` 为 null | 你连的 **不是** 报告那套进程；或代码未同步 / 未 rebuild / 未重启 `dashboard_node` |
| `cameras_meta` 有、页面没有标签 | **只改了后端 JSON，临时前端没进你打开的 www**，或强刷缓存（Ctrl+F5） |
| `camera_streams` 空 / snapshot 404 | 没有 `/camera/*/image_raw`（`gz_physics_proxy` / Gazebo 相机没起来） |
| snapshot 是 PPM 或非 JPEG | 容器缺 **Pillow**，MJPEG 回退 PPM，**Chrome/Edge 的 `<img>` 往往不显示** → 看起来像「没相机」 |
| API 全对、总览像没相机 | 点导航栏 **「三相机」**；总览默认只有前相机一条流 |
