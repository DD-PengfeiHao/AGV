# 18 人脸 ROS2 接通完整技术方案（共享版）

> 版本：v0.2.1 草案 · 日期：2026-08-07  
> 目标：**只接通人脸识别链路**（不做送货/收货业务）  
> 约束：正式通信用 **ROS2**，不用业务 HTTP API  
> 适用：NUC/Ubuntu 验证机 ↔ Jetson（人脸，IP 后期固定）  

**请把本文整份转发给人脸同事（Leo）+ 系统侧同事。**  
文末 **§9「需要共享给他的信息」** 可单独复制。

## 1. 目标与非目标

### 1.1 目标（接通）
1. Jetson 与上位机在同一 ROS2 Domain 下互相发现。  
2. 上位机能收到人脸结果：Topic 和/或 Service。  
3. 未连 Jetson 时，上位机用 **stub** 也能走通同一套接口（方便先联调、写日志）。  
4. 全链路有 **详细日志**，下午换 IP 联调可快速定位。  

### 1.2 非目标（本次不做）
- 送货/收货任务编排、导航授权状态机  
- 改 Leo 检测/识别算法、阈值标定、门禁生产指标  
- 工业相机三路真机（另一同事）；人脸现阶段可用 RealSense / 已有输入  

### 1.3 成功标准（验收可说的话）
> 在 `ROS_DOMAIN_ID=30` 下，上位机可 `ros2 topic echo /face/cam_front/detections` 或调用 `/face/identify_face` 得到识别结果；日志文件可追踪每次请求的 trace_id、耗时与失败原因。Jetson IP 仅通过配置修改。

## 3. 总体技术方案

### 3.1 分层

| 层 | 内容 | 归属 |
|----|------|------|
| 算法层 | RealSense/检测/ArcFace/底库/跟踪 | Leo 现有工程（`leo-人脸识别.docx`） |
| 接入层 | ROS2 发布/服务封装 | **本次要补的薄封装**（Jetson 上 1 个节点即可） |
| 汇聚层 | `face_bridge`：stub / 远端聚合 / 日志 | 系统侧仓库 `face_bridge` |
| 观测层 | jsonl 日志 + `/face/status` +（后续）Debug Web | 系统侧 |

### 3.2 两种正式接通模式（推荐 B1）

#### 模式 B1（推荐）：Jetson 出「识别结果」

```text
Leo 算法 → [jetson_face_ros 薄节点] → /face/cam_front/detections
                                      → /face/identify_face（可选）
NUC face_bridge (backend:=remote_topics)
      → 健康检查、日志、必要时原样转发
      → 上位业务只订 /face/*
```

**优点：** 算力在 Jetson；NUC 不搬 TensorRT；和 Leo 现有栈最贴。  

#### 模式 B2：Jetson 只出图，NUC 识别

```text
Jetson → /camera/cam_front/image_raw → NUC face_bridge(+SDK)
```

**仅当** 必须把模型放 NUC 时再用。本次优先 **B1**。

### 3.3 时间阶段

| 阶段 | 何时 | backend | 说明 |
|------|------|---------|------|
| A 现在 | Jetson 未连 | `stub` | 同名接口 + 日志先通 |
| B 下午 | IP 通、DDS 通 | `remote_topics` | 先接「假结果 publisher」再接真算法 |
| C 稳定后 | IP 固定 | 配置写死 | 只改配置文件/环境变量 |

## 4. ROS2 接口规范（双方必须遵守）

### 4.1 公共约定

```bash
export ROS_DOMAIN_ID=30
export ROS_LOCALHOST_ONLY=0
```

- 发行版：**尽量 Humble**。Jetson 若为 Ubuntu 20 / Foxy：  
  - 优先传标准消息；或 **同一份** `delivery_interfaces` 源码各自编译。  
- 相机逻辑名：人脸主路固定 **`cam_front`**（可扩展 left/right）。

### 4.2 Topic / Service 一览

| 类型 | 名称 | 消息类型 | 发布方 | 订阅/调用方 |
|------|------|----------|--------|-------------|
| Topic | `/face/cam_front/detections` | `delivery_interfaces/FaceDetectionArray` | Jetson 或 stub | NUC 业务 / Web |
| Topic | `/face/status` | `std_msgs/String`（JSON） | face_bridge | 观测 |
| Service | `/face/detect_face` | `DetectFace` | Jetson 或 face_bridge | 联调 |
| Service | `/face/identify_face` | `IdentifyFace` | Jetson 或 face_bridge | 联调 |
| Topic（可选） | `/camera/cam_front/image_raw` | `sensor_msgs/Image` | 相机/仿真 | 仅 B2 |

### 4.3 消息字段（FaceDetection）

| 字段 | 类型 | 说明 |
|------|------|------|
| `camera_name` | string | `cam_front` |
| `person_id` | string | 未识别为空 |
| `person_name` | string | 显示名 |
| `confidence` | float32 | 余弦相似度或映射分，需在文档注明语义 |
| `bbox_xywh` | float32[4] | 像素 x,y,w,h |
| `landmarks_2d` | float32[] | 可选 |
| `liveness_ok` | bool | 无活体则 true 占位 |
| `track_id` | string | 跟踪 ID |

`FaceDetectionArray`：`detections[]` + `face_count`。

### 4.4 Service 行为约定

**IdentifyFace**
- 成功：`success=true`，填 `person_id/name/confidence`  
- 无人脸/未匹配：`success=false`，`message` 为 `no_face` / `unrecognized`（**不要抛异常崩节点**）  
- `min_confidence`：请求里 >0 则覆盖默认阈值  

**DetectFace**
- 可只返回框，不填身份  

### 4.5 `/face/status` JSON 建议

```json
{
  "ok": true,
  "backend": "remote_topics",
  "peer": "192.168.0.225",
  "domain_id": 30,
  "camera": "cam_front",
  "last_event": "identify_ok",
  "last_error": "",
  "detections_hz": 5.2,
  "uptime_sec": 120.5
}
```

## 5. 系统侧实现要点（NUC / 仓库）

### 5.1 组件
- 包：`workspace_v02/ros2_ws/src/face_bridge`  
- 接口：`delivery_interfaces` 中 `FaceDetection*` / `DetectFace` / `IdentifyFace`  
- 文档：`docs/15` `docs/17` 本文  

### 5.2 backend 模式

| 值 | 行为 |
|----|------|
| `stub` | 无 Jetson 时生成假结果，验证接口与日志 |
| `remote_topics` | 等待/转发 Jetson 的 `/face/*`；做超时与日志 |
| `colleague_sdk` | 预留：本机调 SDK（非本周必须） |

### 5.3 配置（下午只改这里）

```bash
export ROS_DOMAIN_ID=30
export FACE_JETSON_IP=192.168.0.225    # 固定 IP 后改此一处
export FACE_BACKEND=remote_topics
export FACE_CAMERA_NAME=cam_front
export FACE_LOG_DIR=/var/log/delivery/face
export FACE_LOG_LEVEL=DEBUG
```

或 YAML 参数等价项。

### 5.4 详细日志（必须）

路径：`/var/log/delivery/face/face_bridge_YYYYMMDD.jsonl`

每条字段：`ts, level, event, trace_id, backend, camera, person_id, confidence, latency_ms, peer, msg, error`

必打事件：`boot` `identify_ok/fail` `detect_*` `image_missing` `topic_wait_timeout` `peer_unreachable` `hz_stat` `shutdown`

排障：

```bash
export ROS_DOMAIN_ID=30
ros2 topic echo /face/status
ros2 topic hz /face/cam_front/detections
tail -f /var/log/delivery/face/face_bridge_$(date +%Y%m%d).jsonl
```

## 6. Jetson 侧实现要点（Leo）

### 6.1 现状（来自 leo 文档）
- 平台：Xavier NX，Ubuntu 20.04，Python，RealSense，TensorRT，自有 MJPEG Web  
- **尚无 ROS2 结果出口** → 需加 **薄封装节点**（不重写算法）

### 6.2 推荐做法
在现有 `main.py` 识别回调里，增加：

1. `rclpy` 节点 `jetson_face_ros`  
2. 每次投票确认身份后，填充 `FaceDetection` 并 `publish`  
3. （可选）提供 `IdentifyFace` service，内部调同一匹配函数  

保持 Leo 的 MJPEG Web 可继续用于人工观看；**系统接通只认 ROS2**。

### 6.3 最小「假数据」节点（下午先通 DDS）
算法未接好时，先发一条固定结果，验证跨机 Topic：

```python
# 伪代码要点
# pub = create_publisher(FaceDetectionArray, '/face/cam_front/detections', 10)
# 每秒：person_id='TEST_USER', confidence=0.99, bbox_xywh=[100,80,120,160]
```

系统侧先 `echo` 到假数据 = 网络/接口 OK；再换真结果。

### 6.4 依赖交付
把 `delivery_interfaces` 源码拷到 Jetson 工作空间编译；或协商暂时用 `std_msgs/String` JSON 过渡（需双方同意，正式仍应上正式 msg）。

## 7. 网络与联调流程

### 7.1 前置
```bash
# 互相
ping 192.168.0.225   # Jetson
ping 192.168.0.173   # NUC 示例，换成实际上位 IP
```

### 7.2 Day 流程

**现在（无 Jetson）**
1. NUC：`FACE_BACKEND=stub` 启动 `face_bridge`  
2. `ros2 service call /face/identify_face ...`  
3. 确认 jsonl 日志有 `identify_ok`  

**下午（有网线/IP）**
1. 固定/确认 Jetson IP，写入配置  
2. 两边 `ROS_DOMAIN_ID=30`  
3. `talker`/`chatter` 跨机可见  
4. Jetson 起假 publisher → NUC `topic echo /face/cam_front/detections`  
5. Jetson 切真算法发布  
6. NUC：`FACE_BACKEND=remote_topics`  
7. 查日志：`topic_wait_timeout` 应消失，出现真 `person_id`  

### 7.3 失败对照

| 现象 | 查 |
|------|-----|
| ping 不通 | 网线/IP/网段 |
| ping 通无话题 | DOMAIN_ID、防火墙、多网卡、`ROS_LOCALHOST_ONLY` |
| 有话题无字段 | msg 包是否同一套、是否编过 |
| 有结果但 Web 无 | Web 是否订 `/face/*`（前端后续） |
| 日志无文件 | 目录权限、容器卷挂载 |
