## 3. AGV 同事问的模块名 ↔ 我们怎么命名

同事材料（`note/AGV同事提出的/*.jpg`）讲的是 **ROS2 Nav2 标准栈**。  
**本项目 Demo 真车 = 仙工 Robokit**，没有 1:1 同名节点。对照如下：

| 同事 / Nav2 模块名 | Nav2 职责（同事语境） | **本项目对应命名 / 实现** | 说明 |
|--------------------|----------------------|---------------------------|------|
| `bt_navigator` | 行为树决策「脑」 | **无同名节点**；车端 Robokit 内部任务状态机 | 我们只看 **1020 `task_status`** |
| `planner_server` | 全局路径规划 | **车端 Robokit 规划**；API **3051** `robot_task_gotarget_req` | 不下发 Nav2 path |
| `controller_server` | 局部控制 `/cmd_vel` | **车端闭环**；我们不发 `cmd_vel` 给真车 | Dev 仿真才有 Gazebo 代理运动 |
| `smoother_server` | 路径平滑 | **无 / 车内** | 不暴露 |
| `behavior_server` | 恢复行为 | **无 / 车内**；失败见 `task_status=5/6` | |
| `waypoint_follower` | 多点任务 | Web **`/api/sim/route` + `/api/sim/route/run`**（Dev）；真车可多次 3051 或车端任务链（API 有 3106 等，**本仓库未接**） | |
| `nav2_map_server` | 静态地图 | 车端载入 **smap**；资产 `agv_downloaded/maps/*.smap`；Dev：`smap_sim` | Roboshop「地图管理」 |
| `nav2_amcl` | 定位 | 车端定位；我们读 **1004**（`confidence,current_station`） | 重定位 API 2002/2003 **客户端有常量、主路径未用** |
| `nav2_costmap_2d` | 代价地图 | 车内；状态 API 有「查询代价地图」等，**Dashboard 未订** | Dev 障碍：`/api/sim/obstacles` |
| `collision_monitor` | 安全否决 | 车端急停/阻挡；消息字段有 `blocked/emergency`，**桥接未拉满 1006/1012** | 门禁 G5 待补 |
| `lifecycle_manager` | 生命周期 | **Docker `boot_gazebo_lite.sh` + systemd/compose** | 不是 Nav2 lifecycle |

## 4. 日志系统：做完了吗？详细吗？

### 4.1 结论（诚实）

| 问题 | 答案 |
|------|------|
| **有没有日志系统？** | **有，已落地可用**（JSONL + HTTP 查询 + 部分人脸分文件） |
| **算「做完」吗？** | **MVP 完成，工业级未完成** |
| **够不够细？** | **关键联调事件有**；缺统一 trace 贯穿、缺全 API 访问审计、缺急停/阻挡等车端字段落盘、缺自动按门禁归档 |

### 4.2 已实现（可依赖）

**实现文件**：`workspace_v02/ros2_ws/src/delivery_web/delivery_web/system_logger.py`

- 类：`SystemJsonlLogger`  
- 目录：`/var/log/delivery/system/system_YYYYMMDD.jsonl`（compose 挂到 `.run/docker_data/volumes/logs_v02/`）  
- 内存环缓：最近约 4000 条；`query(limit, kind, level, event, contains)`  
- HTTP：`GET /api/system/logs`（别名 `/api/logs`）  
- 环境文件：`/var/log/delivery/env.json`（`DELIVERY_ENV_FILE`）  
- 人脸另档：`/var/log/delivery/face/face_bridge_YYYYMMDD.jsonl` → `/api/face/logs`  
- Debug UI：`www/debug/index.html` 可按 kind 滤日志  

**单条记录字段：**

```json
{
  "ts": "ISO-8601 UTC",
  "t": 1234567890.123,
  "level": "INFO|WARN|ERROR|DEBUG",
  "kind": "system|agv|camera|lidar|map|...",
  "event": "事件名",
  "trace_id": "12位hex",
  "msg": "人读说明",
  "error": "",
  "extra": { }
}
```

**已打点的典型 event（不完全表）：**

| kind | event 例 |
|------|----------|
| system | 启动、`env_switch` |
| agv | `robokit_ready`/`fail`、`agv_lock_ok`/`fail`、`navigate_req`/`res`/`fail`/`blocked` |
| camera | 帧/诊断相关、`camera_stream_open`、snapshot 失败等 |
| lidar | `laser_fail` |
| map | `smap_loaded` |

### 4.3 未做完 / 不够细（TRAE 若增强日志可做）

1. **不是每个 HTTP API 都 access-log**（很多 GET 无 slog）  
2. **`trace_id` 每次默认新建**，导航请求→响应→1020 轮询 **未强制同一 trace 串起来**  
3. **Robokit 原始请求/响应未落盘**（排真车协议问题要靠 TRAE 报告手贴或自己加 dump）  
4. **急停 / blocked / 通信中断** 无专门 event；断线后 UI 陈旧态无「stale」级别日志规范  
5. **`camera_ingress` / Xavier 节点** 有独立 logger 意图，与 dashboard slog **未完全统一 schema**  
6. **无按门禁 G1–G7 自动出报告**；要靠 TRAE 人工 `reports/`  
7. **无日志轮转策略文档**（仅按日文件名；环缓 4000 条查询上限 500）  
8. docs/23 对相机主路径描述可能过期，日志 kind=`camera` 的解读以 docs/25 为准

### 8.3 `/api/navigate` HTTP 参数（Demo 模式新增）

| 字段 | 类型 | 默认 | 作用 |
|------|------|------|------|
| `target_id` | string | 必传 | 目标站点 ID（如 "LM2"） |
| `wait` | bool | true | 是否阻塞等导航完成（120s） |
| `reloc_threshold` | float | **0.85** | confidence 低于此值则强制走 relocate |
| `force_reloc` | bool | false | 即便 confidence 高也强制 relocate |
| `reloc_length` | float | 0.5 | 2002 重定位区域半径 m |
| `reloc_timeout` | float | 25.0 | `wait_reloc_done` 超时 s |
| `skip_reloc` | bool | false | 完全跳过 relocate 做 A/B 对照（验证用） |

**默认调用**：`POST /api/navigate {"target_id":"LM2"}` → 自动按 0.85 阈值决策。

**强制走 relocate**：`POST /api/navigate {"target_id":"LM2","force_reloc":true}`。

**完全跳过 relocate 对照**：`POST /api/navigate {"target_id":"LM2","skip_reloc":true}`。

### 8.4 relocate 决策逻辑（核心三条）

```
should_reloc = force_reloc  OR  (confidence_pre < reloc_threshold)  OR  (current_station_pre == "")
```

| 触发条件 | 含义 | 典型场景 |
|----------|------|----------|
| `force_reloc=true` | 调用方显式强制 | 现场 SOP 要求每次导航前都重定位 |
| `confidence < 0.85` | 车端自报定位置信度低 | 车被搬过/断电重启后假定位 |
| `current_station == ""` | 车端找不到最近站点（>0.3m 偏离所有站点） | 车停在站点外/地图漂移 |

**默认阈值 0.85 来自**：交接书 §3 现场经验 + 1004 文档示例 confidence=0.637 显然过低。可在 HTTP 调用时覆盖。

### 8.6 风险与边界

1. **2002 触发后车端可能微动**：交接书 T0.4 "低风险站"原则仍适用——不要在悬崖/楼梯口附近触发 relocate。`reloc_length=0.5m` 是保守半径。
2. **2003 新固件无需调用**：RBK3.4.6.18+ 文档明说"无需再次调用确认定位 API"。客户端 `allow_benign_error=True` 会吞 60001/unknown api/version 错误，不 propagate。**真车小版本号未知**（1004 不返回），所以代码保守地总是尝试调一次。
3. **relocate 后 confidence 仍低**：代码会 `LOG.warning "POST-RELOC LOW CONFIDENCE"`，但**仍继续 3051**（不阻塞）。调用方可通过响应 `reloc.post_reloc_still_low=true` 判断要不要 cancel。
4. **取消导航 3003 与取消重定位 2004 区分**：3003 取消 3051 导航任务；2004 取消 2002 重定位过程。Dashboard `/api/cancel` 只发 3003，**不发 2004**。若 relocate 卡住需要手动 cancel，得直接调 `robokit_client.cancel_reloc()`。
5. **`source_id="SELF_POSITION"`**：~~原代码 3051 始终带此字段~~。**2026-08-07 修正**：AGV 同事 2026-07-28 在 192.168.18.198 实测，3051 加 `source_id` 任何值（含 `SELF_POSITION`）都报错，只有 `{"id":"<目标>"}` 才成功（同事备注"选择经过地图中存在的路线和中间站点，抵达 LM3"）。**代码已改为默认不传 `source_id`**（[robokit_client.py:220-252](file:///home/ubuntu/Pengfei.Hao/AGV_Delivery_v0.2.0_20260807_0921/workspace_v02/ros2_ws/src/agv_bridge/agv_bridge/robokit_client.py#L220-L252) + [dashboard_node.py:1382-1394](file:///home/ubuntu/Pengfei.Hao/AGV_Delivery_v0.2.0_20260807_0921/workspace_v02/ros2_ws/src/delivery_web/delivery_web/dashboard_node.py#L1382-L1394)）。这与官方文档"source_id 必填"矛盾——**以真车实测为准**，文档不可信。Case 7 验证：`goto_station(target_id="LM3")` 默认调用发送的 payload 是 `{"id":"LM3"}` 不含 source_id。
