## 3. 假成功根因（已记录，短期治理）

**Dev 与 Demo 两套控制实现：**

| 模式 | 实际路径 |
|------|----------|
| Dev | Gazebo / `agv_gazebo_nav` |
| Demo | **Dashboard → RobokitClient（直连）** |
| 另存 | `agv_bridge_node`（soft 默认常不起） |

因此：**Dev smoke 对 Demo 真车证明力很弱。**

### 正式 Demo 前强制约定（短期不重构也要守）

**同一时刻只允许一个组件有权连接并控制真车：Dashboard 或 `agv_bridge_node`，另一条在运行配置中禁用。**  
Roboshop 仅配置/诊断；联调控车前必须释放锁。

切换时必查脏状态：锁持有者、导航轮询/socket、Dev 站点列表带入 Demo、激光/位姿带来源与 `updated_at`、断线后是否仍显示最后一帧正常、`/api/env` 失败回滚、`env.json` vs `devices.yaml` 唯一真源。

## 5. 真车最小业务验收清单

除「去某站成功」外至少覆盖：正确站点成功、错误站点拒绝、锁被占用、任务中取消、急停/障碍、低置信度、网络中断、Dashboard 重启、连续两单、返回原点。  
每项核对：车体动作、1020、Web 态、锁最终释放。

另现场确认：地图版本、站点 ID≠显示名、角度/坐标、粘包/分帧、序号匹配、重连旧响应、控制权租约、任务已接受但不可规划、时钟偏差、多客户端轮询、置信度恢复策略、急停/障碍/充电字段固件差异。
