## 〇、总览

- **知识库名称**：Robokit API 通信协议（飞书云文档 Wiki）
- **两大分支**：`ModbusTcp API` 与 `TCP/IP API`
- **协议本质**：基于 TCP 的 request / response 问答式通信。机器人作为**服务器**，接受客户端请求并作出响应。
- **报文组成**：请求 = 头部（定长，标识基本信息、数据区长度与类型）+ 数据区（序列化后的 JSON）；响应同理。
- **适用对象**：RBK（Robot Base Kernel）3.4 / 3.5 等版本的 AGV / 移动机器人。

## 二、核心概念与协议框架（可读文档原文归纳）

### 2.1 API简介
- Robokit 向用户开放机器人操作的相关 API，整套 API 采用 **TCP request/response** 问答方式：机器人作服务器，接受客户端请求并响应。
- API 请求由**头部 + 数据区**组成：头部定长，用于标识数据包基本信息及数据区长度/类型；数据区为序列化后的 JSON，按头部类型反序列化得到对应 JSON 对象。
- 响应同样由头部 + 数据区组成，头部为根据请求得到的定长字节，数据区为序列化后的 JSON。
- **API 测试及例程**：测试工具已开源在 GitHub（Qt 编写），源码可作例程参考；编译后的 Windows 单可执行文件可在 Release 下载。另提供 C# 例程链接。
- **API 类别**：状态查询、控制、导航、配置、推送、其他等。

### 2.2 API报文结构（协议头）
报文头部 `ProtocolHeader` 字段如下：

| 名称 | 内容 | 长度（byte） | 描述 |
| --- | --- | --- | --- |
| 报文同步头 | `0x5A` | 1 (uint8) | 报文同步头，用于确定报文头部开始 |
| 协议版本 | `1` | 1 (uint8) | 协议主版本号。RBK3.4 填 `0x01`，RBK3.5 填 `0x02` |
| 序号 | — | 2 (uint16) | 请求与响应的序号（0~65535）；请求包与响应包该字段相同，由 API 使用者自行填入 |
| 数据总长度 | — | 4 (uint32) | 数据总长度，即需要 Robokit 处理的数据总长度 |
| 报文类型（编号） | — | 2 (uint16) | 标识报文类型，即 API 的编号（见各 API 章节） |
| 内部使用区域 | — | 6 (uint8[6]) | 程序内部使用（无需关注，内容可能非 0 且会变化）；第 3、4 位作路由区长度；第 5 位作压缩类型 |
| 数据区 | — | 取决于头部中数据区长度 | JSON 序列化数据（若同时含路由区与数据，则为二者拼接字符串） |

对应 C 结构体：
```c
#include <stdint.h>
struct ProtocolHeader {
    uint8_t  m_sync;        // 0x5A
    uint8_t  m_version;     // 0x01 / 0x02
    uint16_t m_number;      // 序号
    uint32_t m_length;      // 数据总长度
    uint16_t m_type;        // 报文类型/API 编号
    uint8_t  m_reserved[6]; // 内部使用区域
};
```

### 2.3 坐标系
Robokit 中存在两套右手坐标系：
- **世界坐标系（地图坐标系）**：右手系，与地图和定位相关的操作均使用它。机器人位置 `(x, y, r)` 即机器人在世界坐标系中的 x 坐标、y 坐标、朝向角 r。原点可在 Roboshop 打开地图时查看，并通过坐标变换工具任意改变。
- **机器人坐标系**：右手系。对差动运动机器人，原点即**两轮轴距的中心点**。机器人自身运动参考此坐标系。

### 2.4 注意事项
1. 所有未特别说明的数值单位均为国际单位（m、rad、m/s 等）。
2. **API 响应编号 = 请求编号 + 10000（0x2710）**，请求与响应一一对应。
3. 不要发送任何非 ASCII 字符；尤其与地图名相关的操作，含中文字符的地图名会被视为非法。
4. 每次返回的数据区 JSON Object 中 Key 的顺序不保证（JSON 未规定顺序）。
5. 若响应数据区 JSON 中有 API 未提及的 key-value，可直接忽略，无需关注其含义。

### 2.5 TCP client 模式（3.4.6.13+ 可用）
- 模型文件中 `TCPClient` 含五项设置：`ip`、`端口`、`超时时间`、`是否重连`、`重连次数`（超时时间为 0 时不设置）。
- 在模型文件设置并保存上传后，Robokit 会尝试连接指定 ip/端口；连接成功后主动发送一个 JSON 报文，字段如下，服务端需响应一个符合 rbk 报文格式的报文（响应仅代表收到，不作处理）。连接成功后服务端可主动发送请求 API。

| 字段名 | 类型 | 描述 |
| --- | --- | --- |
| name | string | 机器人名称 |
| ip | string | 客户端 ip |
| port | number | 客户端端口 |

- 请求 / 响应：同 server 模式。

### 2.6 API使用教程（路径导航标准流程）
本文讨论使用 TCP API 控制机器人实现**连续路径导航**的操作流程。

**关键要点：**
1. **常规路径导航基础流程**（按顺序）：机器人开机 → TCP 连接成功确认启动完成 → 调用 `2002` 重定位 → 调用 `1021` 查询定位状态待完成 → 调用 `2003` 确认定位 → 调用 `3051` 执行路径导航 → 调用 `1020` 查询导航状态待完成。
2. **持续路径导航**：循环重复"调用 `3051` 执行路径导航 + 调用 `1020` 查询导航状态待完成"两步即可。
3. **版本相关特殊规则**：机器人系统版本 ≥ `3.4.6.18` 时，无需调用 `2003` 确认定位 API。
4. **可省略重定位的场景**：若上一次关机时定位正确，且关机后机器人位置未移动，开机后可跳过 `2002` 重定位，查询到定位完成后直接确认定位即可。

**路径导航流程步骤：**
1. 机器人开机
2. 等待机器人启动完成（TCP 连接机器人成功后即为启动完成）
3. 执行重定位 `2002`
4. 查询定位状态，等待定位完成 `1021`
5. 确认定位正确 `2003`（3.4.6.18 以上版本无需再次调用）
6. 执行路径导航 `3051`
7. 查询导航状态，等待导航完成 `1020`
8. 循环执行步骤 6、7 即可实现持续路径导航

> 注意：若上一次关机时定位正确且位置未移动，步骤 3 可省略，查询到定位完成后直接确认定位。

## 四、统一报文格式（适用于所有 API）

所有 API 请求/响应均遵循第二节 2.2 的 `ProtocolHeader` 结构：
- 同步头固定 `0x5A`，版本按 RBK 版本填 `0x01`/`0x02`。
- `m_number`（序号）请求与响应一致；`m_type`（报文类型）即 API 编号。
- 数据区为 JSON；`m_length` 为数据总长度。
- **响应编号 = 请求编号 + 10000（0x2710）**，一一对应（见 2.4 注意事项 2）。
